## Описание выполнения и результаты

### Кейс 1 ЭЛМА — поиск аномалий заявок на закупку

Проанализирован журнал событий, составлены критерии нетипичного поведения и перечень кандидатов для проверки. В результатах указаны факты и ограничения; сами кандидаты не являются доказанными нарушениями. Для анализа использован Python и pandas. Рассмотрено 12 137 событий по 1000 процессам на дату среза; по выбранным критериям получены 74 записи о возможных отклонениях в 64 процессах. Проверены последовательности этапов, роли, возвраты и длительности. 25 событий после указанной в описании даты среза исключены; причины отклонений требуют ручной проверки.

### Кейс 2 ЭЛМА — восстановление процесса по журналу

По последовательностям событий восстановлены наблюдаемые маршруты процесса, их частоты и переходы. Схема показывает наблюдаемое поведение и не доказывает внутренние правила системы. Проанализировано 6508 событий по 1000 заявкам. Выделены 8 полных вариантов, в том числе возвраты на доработку; в отчёте приведены частоты и примеры. Проверено, что таблица вариантов охватывает все 1000 заявок.

### Кейс 3 Синаптик — продуктовые гипотезы

На основе предоставленных данных сформулированы пять гипотез с расчётами и ограничениями. Данные инцидентов не представляют всех пользователей, поэтому их доли нельзя обобщать на всю клиентскую базу. Рассмотрены неуспешные заказы, путь к покупке, возможные повторные триалы, инциденты VPN и достижение лимита трафика. Предложения сформулированы как гипотезы для дальнейшей проверки, а не доказанные причинные связи. Доступных данных недостаточно для обоснования оптимальных лимитов трафика.
